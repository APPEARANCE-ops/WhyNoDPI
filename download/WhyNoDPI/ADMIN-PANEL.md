# Админ-панель и телеметрия WhyNoDPI

## Как это работает

```
WhyNoDPI (Windows)  --heartbeat каждые 60 с-->  Сервер админ-панели (Next.js + SQLite)
       анонимный GUID + версия + ОС + стратегия      хеширует GUID, считает онлайн
        |
        +-- "stop" при выходе --> мгновенный офлайн

Вы  --пароль-->  https://ваш-домен/  -->  дашборд: онлайн, всего, новые, тренд 24 ч
```

1. Клиент WhyNoDPI раз в 60 секунд отправляет на сервер анонимный heartbeat.
2. Сервер считает установку «в сети», если heartbeat был в пределах 150 секунд.
3. Пользователь закрыл приложение — клиент отправляет `stop`, и оно сразу
   уходит в офлайн (без ожидания 150 секунд).
4. Пароль администратора хранится **только** на сервере в виде scrypt-хеша.

## Шаг 1. Разверните сервер админ-панели

Проект панели — это приложение Next.js (см. поставку панели). На своём VPS:

```bash
# Node.js 20+ или Bun, HTTPS обязателен (например, Caddy или nginx + certbot)
bun install
bun run db:push      # создать SQLite-базу
bun run build && bun run start   # прод-режим, порт 3000
```

В `.env` сервера задайте:

```ini
# свой сервер с диском — можно SQLite:
DATABASE_URL=file:/abs/path/custom.db
# Vercel и другие serverless-хостинги — только Postgres:
# DATABASE_URL=postgresql://user:pass@host/db?sslmode=require&pgbouncer=true&connection_limit=1

ADMIN_PASSWORD_HASH=scrypt:16384:8:1:<saltHex>:<hashHex>   # хеш пароля
TELEMETRY_PEPPER=<случайные 64 hex-символа>
SESSION_TTL_HOURS=8
ONLINE_WINDOW_SECONDS=150
```

Сгенерировать хеш нового пароля и «перец» (пароль нигде не сохраняется):

```bash
node scripts/hash-password.mjs "ВАШ_НОВЫЙ_ПАРОЛЬ" --pepper
```

## Шаг 2. Подключите WhyNoDPI к серверу

Пересобирать приложение не нужно — адрес панели задаётся в интерфейсе:

1. WhyNoDPI → **Настройки** → карточка **«Сервер статистики»**.
2. Вставьте адрес панели, например `https://whynodpi.vercel.app`.
3. **«Проверить связь»** — панель должна ответить «Панель отвечает корректно».
4. **«Сохранить»** — статус станет «Отправка включена: …».

Галочка «Отправлять анонимную статистику» должна быть включена. Адрес хранится в
`%LOCALAPPDATA%\WhyNoDPI\settings.json`.

Если нужно, чтобы адрес был у всех пользователей «из коробки», есть два пути:
прописать его в `core/TelemetryClient.cs` (`DefaultServerUrl`) и пересобрать EXE,
либо задать переменную окружения `WHYNODPI_TELEMETRY_URL` в системе.

> Для деплоя панели на Vercel (бесплатно, с базой Postgres) есть отдельная
> инструкция: **README-VERCEL.md** в корне проекта.

## Что отправляет клиент

| Поле      | Пример                  | Комментарий                              |
|-----------|-------------------------|------------------------------------------|
| installId | `a1e2f3b4-…`            | случайный GUID, генерируется один раз    |
| version   | `1.2.0`                 | версия приложения                        |
| os        | `Microsoft Windows NT…` | строка ОС                                |
| strategy  | `general.bat`           | выбранный профиль                        |
| event     | `start/heartbeat/stop`  | тип события                              |

Клиент сериализует поля в snake_case (`install_id`), сервер принимает и
`install_id`, и `installId` — формат можно менять без поломки приёма.

Личные данные, пароли, секреты прокси и пути **не отправляются никогда**.
На сервере GUID заменяется на SHA-256(GUID + pepper), поэтому даже полный
дамп базы не позволяет связать статистику с конкретным человеком.

## Пользователь может отключить статистику

В настройках приложения есть галочка «Отправлять анонимную статистику…».
Отключённая телеметрия просто не отправляет heartbeat.

## Безопасность панели (кратко)

- Пароль — только scrypt-хеш в переменной окружения; в коде, БД и клиенте его нет.
- Вход: ограничение 10 попыток / 10 мин и блокировка на 15 минут после 5 неудач.
- Сессия: случайный 32-байтный токен в httpOnly + SameSite=Strict cookie;
  в БД лежит только SHA-256 токена; авто-истечение через 8 часов.
- CSRF: проверка Origin/Referer; cookies SameSite=Strict.
- Заголовки: CSP, X-Frame-Options: DENY, nosniff, no-referrer и др.
- Аудит: входы/выходы/сбросы пишутся в журнал (IP только в виде хеша).
- Телеметрия: zod-валидация, лимит 4 КБ, rate-limit 30 запросов/мин/IP.

## Возможности дашборда

- Ключевые показатели: онлайн сейчас, всего установок, новые за сутки, активные за 24 ч.
- График онлайна за 24 часа по 15-минутным интервалам (с пустым состоянием, пока
  данных нет).
- Распределения по версиям, операционным системам и стратегиям.
- Таблица последних клиентов: поиск, фильтр «Все / В сети / Офлайн», экспорт в CSV.
- Автообновление раз в 10 секунд (можно выключить), индикатор «обновлено N назад».
- Опасная зона с подтверждением словом `УДАЛИТЬ`, отдельным сообщением о результате
  и сохранением журнала аудита.
- Шрифты — системный стек, поэтому сборка не требует доступа к fonts.googleapis.com.
