## 2. Найденные и исправленные ошибки (WPF)

1. **Состояние движка не обновлялось само.** Если `winws.exe` завершался сам,
   интерфейс продолжал показывать «Движок включён». Добавлен опрос состояния
   каждые 3 секунды и обработка «движок умер» (запись в журнал + уведомление,
   повторная проверка сервисов).
2. **Противоречивый интерфейс.** Заголовок брался из одного поля, кнопки — из
   другого, и они могли расходиться (например, «Движок выключен» рядом с
   «Остановить Zapret»). Теперь состояние нормализуется в одном месте.
3. **`ModuleStatus` затирался** при каждом обновлении UI, поэтому сообщения
   «Подготовка профиля…» исчезали мгновенно.
4. **Автоподбор нельзя было отменить.** Добавлена кнопка «Отменить»
   (`CancellationToken`), корректная остановка движка при отмене и восстановление
   кнопок.
5. **После автоподбора выпадающий список включался обратно**, даже если движок
   уже работал — теперь доступность контролов считается из фактического состояния.
6. **Опасная остановка чужого процесса.** Проверки остались, но теперь они
   выполняются по одному снимку состояния, а не по трём последовательным опросам.
7. **Тормоза UI.** `sc query zapret` (до 2,5 с) вызывался в UI-потоке при каждом
   обновлении. Теперь опрос идёт в фоне и с меньшей частотой.
8. **Три перебора процессов `winws`** на каждое обновление → один `GetSnapshot()`.
9. **Журнал без фильтров.** Добавлены уровни (INFO/OK/! /ERR/ENG), цветовая
   разметка, поиск, фильтр «предупреждения/ошибки», копирование и очистка.
10. **Системные `MessageBox`** (яркие белые окна в тёмном приложении) заменены
    собственным диалогом с темами Info/Success/Warning/Danger.
11. **Нет защиты от второго экземпляра** — два процесса могли конфликтовать за
    WinDivert. Добавлен `Mutex` + предупреждение.
12. **Необработанные исключения** роняли приложение молча. Добавлен глобальный
    обработчик и crash-лог в `%LOCALAPPDATA%\WhyNoDPI\logs`.
13. **Название профиля портилось** (`ToLowerInvariant`) — исправлено.
14. **Мёртвый код** (`DiagnoseLaunchFailure`, `ReadLogTail`, `TryDelete`) удалён,
    предупреждения nullable-анализа в `TelegramProxyLinkHelper` устранены.
15. **DPI.** Не было per-monitor awareness — на HiDPI интерфейс был размытым.
    Добавлено в манифест (`PerMonitorV2`, `longPathAware`).
16. **Белая полоса заголовка окна** на тёмной теме — включён тёмный режим DWM и
    скруглённые углы Windows 11.
17. **Не было иконки приложения** — нарисована и встроена (EXE + окно + панель
    задач).

## 3. Интерфейс: что переделано

Полностью новая визуальная система (`Themes/Theme.xaml`) и переписанный
`MainWindow.xaml`.

- **Дизайн-система.** Палитра, типографика, карточки, бейджи, кнопки (primary,
  secondary, ghost, danger, link), переключатели, поля, чипы.
- **Все контролы под тёмную тему.** `ComboBox` (свой шаблон + выпадающий список),
  `TextBox`/`PasswordBox` (с подсказками внутри поля), `CheckBox` превращён в
  современный переключатель, `ProgressBar`, `ScrollBar` (тонкий, скруглённый),
  `ListBox`, `ToolTip` — раньше они оставались системными светлыми.
- **Навигация.** Пункты меню с иконками и активным состоянием (акцентная полоса +
  подсветка), блок состояния движка в сайдбаре.
- **Плавные переходы** между страницами (fade + сдвиг), анимации появления
  уведомлений.
- **Главная.** Крупная hero-карточка состояния с градиентом, кнопками и аптаймом;
  карточки сервисов с индикаторами и задержкой; «Активный профиль»; «Готовность
  пакета» (WinDivert / профили / права администратора); «Последние события».
- **Стратегии.** Выбор профиля, блок прогресса с процентом и кнопкой отмены,
  список результатов с цветными статусами и счётом `N/3` вместо строк-иероглифов.
- **Telegram · VPN.** Две колонки, шаги подключения, подсказки в полях, статусные
  плашки.
- **Журнал.** Панель инструментов (поиск, фильтры, копирование, папка логов,
  очистка), цветные записи, пустое состояние.
- **Настройки.** Путь к пакету с копированием, диагностика, переключатели
  поведения, служебные папки, горячие клавиши, инструкция по обновлению пакета.
- **Статус-бар** внизу окна: состояние движка, профиль, время проверки сервисов.
- **Горячие клавиши:** `F5` — проверить сервисы, `Ctrl+1…5` — разделы.
- **Тосты** вместо модальных окон для рутинных действий («профиль выбран»,
  «путь скопирован», «движок остановлен»).

## 4. Админ-панель (Next.js)

Интерфейс:

- Скелетоны загрузки вместо одинокого спиннера.
- В шапке: живой индикатор, «обновлено N назад», серверное время, спиннер на
  кнопке «Обновить».
- Таблица клиентов: **поиск**, фильтр **Все / В сети / Офлайн**, счётчик
  «показано из всех», **экспорт в CSV**.
- Пустые состояния для таблицы и графика (раньше график молчал).
- Контролируемый диалог подтверждения очистки: закрывается сам, показывает
  результат операции.
- Аккуратные карточки и типографика, статус-бейджи с иконками.

Логика:

- Обработка `429` и ошибок сброса данных (раньше ошибка проглатывалась).
- Защита от обновления состояния после размонтирования.
- Относительное время пересчитывается раз в 5 с, а не каждую секунду
  (перерисовка всей таблицы 25 раз в секунду).
- Убран мёртвый `autoRef`.
- Шрифты — системный стек вместо `next/font/google`: сборка больше не требует
  доступа к fonts.googleapis.com (в вашей сети он закрыт), а кириллица и так
  рендерилась системным шрифтом.
- `.gitignore`: `.env.example` больше не игнорируется (раньше правило `.env*`
  исключало шаблон из репозитория).

## 6. Как собрать и запустить

Десктоп:

```powershell
cd download\WhyNoDPI
dotnet build                     # проверка
.\Build-EXE.ps1                  # публикация одиночного EXE в publish\
```

Готовый EXE (собран здесь): `release\WhyNoDPI.exe`. Его всё равно нужно запускать
от имени администратора — это требование WinDivert.

Админ-панель:

```bash
bun install
bun run db:push
bun run build && bun run start
```

## 7. Обновление 1.2 — панель на Vercel и отправка статистики

### Приложение (десктоп)

- **Адрес панели задаётся в интерфейсе.** Настройки → «Сервер статистики» →
  вставить адрес → «Проверить связь» → «Сохранить». Пересобирать EXE больше не
  нужно: адрес хранится в `%LOCALAPPDATA%\WhyNoDPI\settings.json`.
  Приоритет источников: переменная `WHYNODPI_TELEMETRY_URL` → настройка →
  встроенный адрес по умолчанию.
- **«Проверить связь»** обращается к новому `/api/health` и различает три случая:
  «нет связи», «панель отвечает, но база недоступна», «неверный адрес».
  Раньше единственный способ узнать, что статистика не уходит, — догадаться самому.
- **Исправлен баг вёрстки полей ввода.** Текст в любом `TextBox`/`PasswordBox`
  рисовался со сдвигом вверх и обрезался (двойное применение `Padding` в шаблоне).
  Это было заметно во всех полях: поиск по журналу, поля MTProto-прокси, адрес панели.
- Версия приложения — 1.2.0.

### Админ-панель (Next.js)

- **Готовый SQL для базы** `prisma/schema.postgres.sql` — те же четыре таблицы,
  если не хочется ставить Node.js: вставляется в Neon → SQL Editor → Run.
- **Postgres-схема** `prisma/schema.postgres.prisma` и скрипты:
  `build:vercel` (generate под Postgres + `next build`), `db:push:postgres`,
  `postinstall`. Локальный запуск на SQLite сохранён.
- **`vercel.json`**: регион `fra1`, команда сборки, `no-store` для `/api/*`.
- **`/api/health`** — проверка «панель жива и база доступна» (нужна и приложению,
  и вам после деплоя).
- **Защита от подбора пароля на serverless.** На Vercel каждый холодный старт —
  новый инстанс, поэтому счётчик неудач в памяти не работал. Теперь количество
  неудачных попыток читается из общей таблицы `AuditLog` (`src/lib/login-throttle.ts`).
- **`scripts/hash-password.mjs`** — генерирует `ADMIN_PASSWORD_HASH` и
  `TELEMETRY_PEPPER` одной командой, без ручного `node -e`.
- **`README-VERCEL.md`** — пошаговая инструкция: база Neon, создание таблиц,
  переменные окружения, деплой, проверка, таблица типовых ошибок.
- `next.config.ts`: режим `output: "standalone"` больше не включается на Vercel
  (он нужен только для собственного сервера).

### Панель: сборка и проверка в работе (12.11, 09:40)

Сеть в среде оказалась доступна, поэтому панель удалось собрать и прогнать по-настоящему:

- `pnpm install` + `prisma generate` (Postgres) → **`next build` проходит**,
  TypeScript — без ошибок, маршруты собираются (включая `/api/health`).
- **Найден блокер деплоя:** сборка падала на типах в `examples/websocket/*`
  (импортируют `socket.io`, которого нет в зависимостях). Файлы-примеры из
  шаблона исключены из `tsconfig.json` — иначе Vercel не собрал бы проект.
- **Найден блокер функции целиком:** клиент отправлял `install_id` (snake_case,
  политика `System.Text.Json`), а сервер ждал `installId` → ответ **400
  validation_failed**. То есть статистика не собиралась бы вообще, сколько бы
  людей ни запустили приложение. Сервер теперь принимает оба варианта
  (`z.preprocess` в `api/heartbeat/route.ts`), проверено: snake_case → 202,
  camelCase → 202, мусор → 400.- Локальный прогон на SQLite: создана база, запущен `next start`, проверено:
  - `/api/health` → `{"ok":true,"database":"up"}`;
  - `POST /api/heartbeat` → 202, клиенты создаются;
  - вход паролем → 200 + httpOnly cookie, неверный пароль → 401;
  - `/api/admin/stats` без сессии → 401, с сессией → онлайн/всего/тренд;
  - демо-данные: 15 клиентов, 9 онлайн, 97 точек тренда (после правки схемы — 17 и 11).
- Исправлен путь SQLite: Prisma считает относительный путь от папки `prisma/`,
  поэтому `file:./db/custom.db` создавал базу в `prisma/db/`. Теперь
  `file:../db/custom.db` — файл лежит в `db/`, как и описано в документации.

Живая панель с демо-данными: `http://localhost:3000` (пароль — в
`АДМИН_БЫСТРЫЙ_СТАРТ.md`).

## 8. Обновление 1.3 — проверка обновлений и сетевой прокси

- **Карточка «Обновления»** в настройках: WhyNoDPI сравнивается с версией из
  `/api/version` панели, пакет Flowseal — с последним релизом GitHub. Плюс
  автопроверка при запуске (не чаще раза в 30 минут) и уведомление при находке.
- **Новый роут панели** `/api/version`: актуальную версию и ссылку на скачивание
  задают переменные `APP_LATEST_VERSION`, `APP_DOWNLOAD_URL`, `APP_RELEASE_NOTES` —
  выпускать обновление можно без правки кода и пересборки.
- **Найден и исправлен серьёзный баг:** на машине включён «мёртвый» системный
  прокси `127.0.0.1:8080`, и .NET-клиенты ходили через него. Из-за этого молча не
  работали **телеметрия и проверка обновлений** (запросы падали в никуда). Оба
  клиента теперь ходят напрямую (`UseProxy = false`), как уже делала проверка
  сервисов. Проверено вживую: приложение отправило `start`/`stop` в панель, запись
  появилась в статистике с версией `1.3.0`.
- **Подсказка «профиль слабый».** После включения движка приложение проверяет
  сервисы: если открылось меньше двух из трёх, оно честно пишет «движок работает,
  но сервисы почти не открываются» и предлагает автоподбор — вместо тихого
  «всё включено», когда обход фактически не помогает.
- **Две готовые сборки:** `WhyNoDPI-1.3-Admin.exe` (для вас, адрес панели в
  настройках) и `WhyNoDPI-1.3-Client.exe` (для пользователей, адрес вшит).- Проверено на реальных данных: `1.3.0 → 1.4.0` даёт «доступна 1.4.0»,
  `1.4.0 → 1.4.0` — «актуальная»; Flowseal: пакет от января → «доступен от
  20.10.2026» (релиз 1.10.4), свежий пакет → «актуальный».
## 9. Что осталось непроверенным

- Админ-панель проверена локально на SQLite и собрана под Postgres, но **на
  Vercel не разворачивалась**: для этого нужны ваши аккаунты Vercel и Neon.
- Запуск `WhyNoDPI.exe` не выполнялся: приложение требует UAC-подтверждение.
  Проверены компиляция, публикация и постраничная отрисовка интерфейса.
- Реальный обход блокировок (winws.exe + WinDivert) зависит от вашей сети и
  пакета Flowseal — это проверяется только на рабочей машине.
