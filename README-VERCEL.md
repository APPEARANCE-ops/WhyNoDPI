# WhyNoDPI Admin Panel → Vercel

Пошаговая инструкция: как поднять панель на Vercel и увидеть, сколько людей
запускают WhyNoDPI.

---

## Сначала главное: почему нельзя просто нажать Deploy

Панель хранит данные в базе. Сейчас в проекте SQLite (`db/custom.db`) — это файл
на диске. **На Vercel файловой системы нет**: функции выполняются в изолированных
контейнерах, диск только для чтения, а `/tmp` не переживает запрос. Панель
задеплоится, но:

- вход в админку будет падать с ошибкой базы;
- heartbeat от приложения не будет сохраняться.

Поэтому для Vercel база переводится на **Postgres** — в проекте уже есть готовая
схема `prisma/schema.postgres.prisma` и скрипт сборки `build:vercel`, который
генерирует Prisma-клиент под Postgres. Локально можно продолжать работать на
SQLite: схемы независимы.

```
WhyNoDPI.exe ──heartbeat раз в 60 с──▶ https://ваш-проект.vercel.app/api/heartbeat
                                              │
                                       Postgres (Neon / Vercel Postgres)
                                              │
вы ──пароль──▶ https://ваш-проект.vercel.app ─┘  → дашборд: онлайн, всего, тренд
```

---

## Шаг 0. Что понадобится

- Аккаунт [vercel.com](https://vercel.com) (бесплатного Hobby достаточно).
- Бесплатная Postgres-база: [Neon](https://neon.tech) (проще всего) или
  Vercel → Storage → Postgres.
- Node.js 20+ на своём компьютере (для `prisma db push` и генерации хеша пароля).

---

## Шаг 1. База данных

1. Зарегистрируйтесь на [neon.tech](https://neon.tech) и создайте проект
   (регион — Europe / Frankfurt, ближе к пользователям).
2. Откройте **Connection string** и скопируйте **две** строки:

| Что | Как выглядит | Куда |
|---|---|---|
| Pooled (с `-pooler` в хосте) | `postgresql://user:pass@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require` | `DATABASE_URL` на Vercel |
| Direct (без `-pooler`) | `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require` | один раз для `prisma db push` |

Для serverless к pooled-строке полезно добавить параметры:

```
...?sslmode=require&pgbouncer=true&connection_limit=1
```

---

## Шаг 2. Пароль админки и «перец»

В папке проекта:

```bash
node scripts/hash-password.mjs "мой-длинный-пароль" --pepper
```

Скрипт напечатает два значения:

- `ADMIN_PASSWORD_HASH` — `scrypt:16384:8:1:<salt>:<hash>`;
- `TELEMETRY_PEPPER` — 64 случайных hex-символа.

Пароль в открытом виде никуда не сохраняется. Если потеряете — сгенерируйте хеш
заново и обновите переменную.

---

## Шаг 3. Создать таблицы в Postgres

Нужны четыре таблицы. Есть два способа — выбирайте любой.

### Вариант А — через Prisma (нужен Node.js)

Один раз, со своего компьютера, **с direct-строкой** (не pooled):

```bash
# Windows PowerShell
$env:DATABASE_URL="postgresql://...без -pooler..."
npx prisma db push --schema prisma/schema.postgres.prisma

# macOS / Linux
DATABASE_URL="postgresql://...без -pooler..." npx prisma db push --schema prisma/schema.postgres.prisma
```

Перед этим в папке проекта должен быть выполнен `npm install` (или `bun install`),
иначе `prisma` не найдётся.

Ожидаемый результат: `Your database is now in sync with your Prisma schema`.

### Вариант Б — без Node.js, через SQL Editor

1. Neon → ваш проект → **SQL Editor**.
2. Откройте файл `prisma/schema.postgres.sql` целиком, скопируйте его содержимое.
3. Вставьте в редактор и нажмите **Run**.

Скрипт идемпотентный (`IF NOT EXISTS`), повторный запуск ничего не сломает.
Имена таблиц, колонок и индексов совпадают со схемой Prisma, поэтому оба способа
дают одинаковый результат.

> `db push` создаёт таблицы без истории миграций — для этой панели этого
> достаточно. Если позже понадобятся миграции, переходите на `prisma migrate`.

## Шаг 4. Деплой на Vercel

### Вариант А — через Git (рекомендуется)

1. Залейте проект в GitHub/GitLab.
2. Vercel → **Add New → Project** → выберите репозиторий.
3. Framework Preset определится как **Next.js**, команду сборки менять не нужно:
   она берётся из `vercel.json` → `npm run build:vercel`
   (он делает `prisma generate` под Postgres и затем `next build`).
4. В **Environment Variables** добавьте:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | pooled-строка из шага 1 (с `pgbouncer=true&connection_limit=1`) |
| `ADMIN_PASSWORD_HASH` | из шага 2 |
| `TELEMETRY_PEPPER` | из шага 2 |
| `SESSION_TTL_HOURS` | `8` (необязательно) |
| `ONLINE_WINDOW_SECONDS` | `150` (необязательно) |
| `APP_LATEST_VERSION` | `1.3.0` (необязательно) — какую версию WhyNoDPI считать актуальной |
| `APP_DOWNLOAD_URL` | ссылка на скачивание (необязательно) |
| `APP_RELEASE_NOTES` | текст для уведомления (необязательно) |

5. **Deploy**.

### Вариант Б — через CLI

```bash
npm i -g vercel
vercel login
vercel link
vercel env add DATABASE_URL production    # вставить pooled-строку
vercel env add ADMIN_PASSWORD_HASH production
vercel env add TELEMETRY_PEPPER production
vercel --prod
```

Регион уже задан в `vercel.json` (`fra1`, Франкфурт).

---

> **Обновления приложения.** Клиентская проверка версий берёт данные из
> `/api/version`. Меняете `APP_LATEST_VERSION` и `APP_DOWNLOAD_URL` в Vercel —
> приложение сразу начинает показывать «Доступна новая версия», без пересборки.

## Шаг 5. Проверить, что всё живо

1. Откройте `https://ваш-проект.vercel.app/api/health`.

   Должно быть:

   ```json
   { "ok": true, "service": "whynodpi-panel", "database": "up" }
   ```

   Если `"database": "down"` — неверный `DATABASE_URL` или не выполнен шаг 3.

2. Откройте `https://ваш-проект.vercel.app` и войдите паролем из шага 2.
   Если вместо формы входа написано «Пароль не настроен на сервере» — переменная
   `ADMIN_PASSWORD_HASH` не попала в окружение (после изменения переменных нужен
   redeploy).

---

## Шаг 6. Подключить приложение

Статистику отправляет сама программа WhyNoDPI, поэтому адрес панели нужно указать
у неё — пересобирать EXE не нужно:

1. Откройте WhyNoDPI → **Настройки**.
2. В карточке **«Сервер статистики»** вставьте `https://ваш-проект.vercel.app`.
3. Нажмите **«Проверить связь»** — должно появиться «Панель отвечает корректно».
4. Нажмите **«Сохранить»**. Статус станет «Отправка включена: …».
5. Галочка «Отправлять анонимную статистику» должна быть включена.

Через минуту в панели появится ваша установка: «В сети сейчас — 1» и строка в
«Последние клиенты».

> Если вы раздаёте EXE другим людям, адрес панели у них по умолчанию пустой.
> Варианты: (а) попросить их вписать адрес в настройках, (б) прописать адрес
> по умолчанию в `core/TelemetryClient.cs` → `DefaultServerUrl` и пересобрать
> EXE через `Build-EXE.ps1`, (в) задать переменную окружения
> `WHYNODPI_TELEMETRY_URL` в системе.

## Что показывает панель

- **В сети сейчас** — установки, у которых heartbeat был за последние 150 секунд.
- **Всего пользователей** — уникальные установки за всё время.
- **Новые сегодня** / **Активны за 24 часа**.
- **График** — онлайн по 15-минутным интервалам.
- **Версии / ОС / стратегии** — распределения.
- **Последние клиенты** — таблица с поиском, фильтром и экспортом в CSV.

Идентификатор установки — случайный GUID, на сервере он хранится только как
SHA-256 от GUID + `TELEMETRY_PEPPER`. Ни IP, ни путей, ни паролей приложение не
отправляет.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| `/api/health` → `"database": "down"` | неверный `DATABASE_URL` или таблиц нет | проверить строку, выполнить шаг 3 |
| Сборка падает на `prisma generate` | `prisma` не установился (devDependencies) | в Vercel Settings → General → Install Command оставить пустым; проверить логи сборки |
| Вход: «Пароль не настроен на сервере» | нет `ADMIN_PASSWORD_HASH` | добавить переменную и нажать Redeploy |
| Вход: 429 / «Слишком много попыток» | сработала блокировка после 5 неудач | подождать 10 минут |
| Приложение: «Нет связи с панелью» | опечатка в адресе, проект в Vercel на паузе | проверить `/api/health` в браузере |
| В панели 0 пользователей | у клиента выключена телеметрия или не задан адрес | Настройки → «Сервер статистики» → Проверить связь |
| График пустой, но клиенты есть | снимки онлайна пишутся с первым heartbeat | подождать минуту |
| Локально после `db:generate:postgres` падает `bun dev` | локальный клиент Prisma теперь Postgres | выполнить `npm run db:generate` (SQLite) |

## Безопасность и ограничения

- Пароль — только scrypt-хеш в переменных окружения Vercel.
- Сессия — случайный токен в httpOnly + SameSite=Strict cookie; в БД лежит его
  SHA-256; срок жизни 8 часов, продлевается автоматически.
- Блокировка подбора пароля на Vercel считается по общей таблице `AuditLog`,
  а не по памяти инстанса (см. `src/lib/login-throttle.ts`).
- Rate limit heartbeat (30 запросов/мин на IP) остаётся в памяти инстанса — это
  защита от простого флуда, а не биллинговый лимит.
- Hobby-план: функция живёт до 10 с — панели этого хватает с запасом.
- Бесплатный Postgres (Neon) хранит данные постоянно, но у бесплатных тарифов
  есть лимит объёма; старые снимки онлайна чистятся автоматически (7 дней).

## Локальный запуск (как раньше, SQLite)

```bash
bun install
bun run db:push      # создаёт db/custom.db
bun run dev
```

Этот режим не изменился: `dev`, `build`, `start` работают с SQLite и
`prisma/schema.prisma`.
